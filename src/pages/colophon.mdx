A colophon states how a thing was made. Everything on this page lives in the
[public repository](https://github.com/thpham/blog), where a test suite that
builds the site twice — with the demo content, and without it — keeps this
list honest.

## The stack

- [Astro](https://astro.build) 7.4.0, on Node.js 24: Markdown and MDX in
  content collections, with every entry's frontmatter validated by Zod
  schemas at build time — a schema violation fails the build instead of
  shipping a wrong page.
- Three typefaces, self-hosted at build time through Astro's Fonts API:
  Newsreader for the titles and the running text, Instrument Sans for the
  interface, IBM Plex Mono for the metadata. No font CDN is requested at
  runtime.
- Code blocks coloured by [Expressive Code](https://expressive-code.com),
  with a custom theme wired to the site's design tokens.
- Mermaid diagrams rendered at build time, twice (light and dark), in a
  headless Chromium.
- Excalidraw drawings kept as sources next to the article, exported to one
  light and one dark SVG by the script under `tools/excalidraw`.
- The Open Graph image of the home page and of every entry, drawn by satori
  and resvg at build
  time — the 1200×630 card you see in link previews.
- Full-text search by [Pagefind](https://pagefind.app), indexing only the
  entries, never the furniture.
- Feeds in RSS and Atom (including the old URLs of the previous site), the
  sitemap, `llms.txt` and a Markdown copy of every published article: all
  generated by
  the build.
- Tested with [Vitest](https://vitest.dev): unit tests over the pure
  helpers, and build tests over two production builds — the site as you see
  it, and the same site with the demo content deleted, which must still
  build and stay presentable.
- Hosted on [GitHub Pages](https://pages.github.com) at blog.ithings.ch,
  deployed by Actions on every merge to main. No analytics runs today; the
  build ships a counter only when one is configured, and never a consent
  banner.

## The logo

The wordmark is not drawn by hand; it is measured out of the font.

- The letters are outlined from **Instrument Sans** at weight 600, with a
  tracking of −0.025 em, shaped with HarfBuzz and traced with FontTools. The
  font travels with the script, under its SIL Open Font License 1.1, whose
  full text ships beside it as
  [OFL.txt](https://github.com/thpham/blog/blob/main/tools/logo/OFL.txt).
- The first letter is set as a dotless `ı`. Its stem axis is measured in the
  font: it sits at **x = 130.0/1000 em** at weight 600, and the dot and both
  signal arcs are centred on exactly that axis.
- Both dots are discs, enlarged by 8 % over the font's own tittle — optical
  compensation. The first is the accent colour and emits two concentric
  arcs, ±48° open, at opacities 0.9 and 0.5; the second stays in the text
  colour.
- The letters use `currentColor`, the arcs and the dot read the accent
  variable, so the mark follows the theme switch like every other drawing
  on the site. The favicon is the same mark, standalone, with its colours
  written inline.

Regenerate it with:

```sh
cd tools/logo
uv run --with fonttools --with uharfbuzz python wordmark.py 600 round
```

## The isolines

Every entry of this site draws its own terrain. An FNV-1a hash of the
entry's `<collection>/<id>` seeds a small Park–Miller generator, which
places a few gaussian hills over a slight undulation; marching squares then
traces the contour lines into plain SVG paths — fifteen levels, every fourth
line an index line drawn heavier, the way a topographic map reads. The same
entry always draws the same terrain.

The whole drawing happens at build time: the home hero, the article
headers, the preview panel, the Open Graph images and the rings of the tech
radar all get their terrain from the same generator, in `src/lib/isolines.ts`.

## The editorial pipeline

The content is Markdown and MDX files in the repository — no database, no
CMS, no server-side rendering. The schemas check the frontmatter,
TypeScript checks the code, and the tests re-build the site with and
without the demo content before anything ships. Publishing is a merge into
the main branch: Actions builds and deploys to GitHub Pages, and the result
is a folder of files, served as they are.
